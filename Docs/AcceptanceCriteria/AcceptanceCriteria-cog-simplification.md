# AcceptanceCriteria — THE COG SIMPLIFICATION (cables die · OMNI default · doors become lenses)
_From the design side (INSTRUCTIONS-cog-simplification, 2026-08-03). The user's ruling: the cog is confusing;
cables on the way IN are router-admin the host already owns. Redesign the COG (CogPage) around a "lens, not a
socket" identity for the four receiver doors._

## 1. CABLES — GONE FROM THE UI
- The plugin ALWAYS accepts all input cables, silently (union). NO cable selector anywhere.
- Also deletes a host-compat variance.
- AUM/upstream remains where streams are routed INTO the plugin (the user's own upstream doctrine).

## 2. CHANNELS — OMNI DEFAULT, ONE OPTIONAL CHIP
- Every receiver defaults **CH: OMNI** (hears everything).
- Separation for multi-controller rigs = ONE chip per door: `CH: OMNI | 1–16`. Basic users never face a decision;
  the two-keyboard story survives as one tap.

## 3. THE DOOR'S NEW IDENTITY (doc line, no build)
A LENS, not a socket — four doors on one stream, differently shaped (CHORD latch · ADD sculpture · OCT−12 bass
lens · dry) is the zero-config value.

## 4. THE COG'S NEW SHAPE — one line per door
- Per-door row: `[hue · label]` · `[CH chip, OMNI default]` · `[LATCH: CHORD | ADD]` · `[MPE toggle + indicator]`.
- THRU stays on the strip (performance-adjacent, unchanged).
- Below: the emitter channel row (ch1–4 as-is) · true globals only (the cog admission law re-asserted).
- Everything else the page currently shows that isn't the above: audit against the admission law and evict or justify.
