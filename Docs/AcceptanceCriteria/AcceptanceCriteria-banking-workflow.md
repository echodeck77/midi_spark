## THE FOUR SEMANTIC PINS
1. **EDIT TARGET vs BANK TARGETS.** The selected row = the LIVE
   edit target (colour-owned edits apply to it continuously). The
   strip's other chips = one-shot COPY-TO stamps. The current
   row's chip renders differently: **EDITING** (filled + a live
   mark) vs **tap-to-overwrite** (outlined). You can never
   confuse "who am I shaping" with "where am I dealing."
2. **BANKING IS A SNAPSHOT, not a link.** After tapping row 2,
   further tweaks do NOT ripple there — the banked row is a
   stamped sibling (a fork at stamp-time). That's the point:
   variations by iteration.
3. **THE EDITOR STAYS after banking** — you keep sculpting the
   same evolving machine and deal again. Switching the edit
   target = the LEFT panel's row chips (or DONE + reselect),
   never the strip.
4. **ROWS OWN THEIR HUE.** The gradient is row identity; banking
   stamps CONTENT into the row's own colour. Machines move
   between rows; the ladder's rainbow never scrambles.

## THE CLARITY SET (small, all display)
- **Occupied vs empty strip chips**: rows holding content render
  FILLED, empty rows HOLLOW — what a tap would destroy is visible
  before the tap (display ⊇ offer).
- **The stamp tell**: the tapped chip FLASHES + "ROW n ✓"; one
  undo step per bank.
- **HOLD a strip chip = preview that row's existing machine**
  (the spring grammar) — hear what you'd overwrite. Optional;
  cheap; recommended.
- **The audition runs through the whole loop** (config never
  stops): tweak → hear → bank without a single transport touch.
  The manual teaches the loop in one line: "Shape one machine;
  deal its best moments to the rows."
