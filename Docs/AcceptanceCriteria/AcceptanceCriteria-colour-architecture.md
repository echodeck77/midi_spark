# INSTRUCTIONS → Code — THE COLOUR ARCHITECTURE (Paul, 2026-08-12:
# "colour highlights what's what" — the page's three channels)

## 0. THE MUTED-CHROME LAW (Paul's instinct, made the rule)
All chrome OUTSIDE the grids — buttons, panels, section labels,
handles — drops to the neutral/dim palette; the standing cyan/pink
accents reduce to whispers (armed/primary states only). **The
page's only sustained saturation = the grid cells + the selected
hue's tinted elements.** Defaults recede; the selection announces.
Pick red, and red is the loudest thing on screen — because
everything else just got quieter.

## 1. CHANNEL ONE — HUE = WHICH MACHINE
The selected colour tints (as built: the chain slots) and EXTENDS:
**THE THREAD** — a thin (~2pt, low-alpha) hue edge running from
the selected cast swatch DOWN the left column and INTO the footer
chain's frame, so the column and footer read as ONE OBJECT: the
machine's anatomy, input → thread → chain → output. The armed-verb
grid rim keeps the hue. Hue is NEVER used for focus or part
identity.

## 2. CHANNEL TWO — BRIGHT-INK = WHICH PART
The current part's presence links across all three zones with a
NEUTRAL brightening (no second hue system): **the PART ▾ chip's
underline · the staging frame · the deployed band's RAIL bracket
on the play grid** share the bright-ink accent; all other bands'
rails sit dim. One glance answers "where does this part live" —
workshop, and its seat on stage. (Parts have no hue of their own;
brightness is their voice.)

## 3. CHANNEL THREE — THE FRAME = WHICH ZONE SOUNDS
The focus/voice frame (the PLAYING accent border, as built) stays
the zone-level channel. Never hue-tinted, never part-linked.

## The law, one line
**HUE says machine · BRIGHTNESS says part · THE FRAME says voice**
— three questions, three channels, no borrowing. With the chrome
muted beneath them, each answer is the loudest thing of its kind.
Implementation: alpha ladder suggested — chrome ~40–55% ink ·
part-bright ~90% · hue tints 25–35% fills / full-sat edges;
Paul's eye tunes on glass.
— design-side Claude

## §4 — THE BAND LENS (Paul, 2026-08-12: recolour-on-deploy —
## ruled SAFE with four safeguards)
- **The mechanism**: each band owns a HUE FAMILY; at deployment
  the part's colours RE-MAP into it, PRESERVING relative
  distinctions (gold+orange → teal+cyan: two machines stay two
  hues). A DISPLAY LENS over unchanged colourIDs — **never a
  fork**: references, colour-owned editing, twins, seals all
  intact underneath.
- **The four safeguards**:
  ① Lens, not identity — the underlying colour never changes;
  ② Within-grid consistency — same machine = same displayed hue
  everywhere on that grid (the map is per-band, deterministic);
  ③ **LAST TOUCHED + the footer ID chip always show the TRUE
  cast hue** (a small band-lens glyph beside it) — the bridge
  stays honest across the costume change;
  ④ The play-grid hue channel re-reads as: BAND first,
  machine-within-band second (the three-channel law's stated
  amendment, not an accident).
- **The costume law, made literal**: the colour is the costume;
  THE BAND DRESSES ITS MEMBERS. Cross-grid recognition is traded
  for rail legibility — a fair trade on stage, where seats
  outrank faces.
- **The cheaper alternative, held in reserve** (if the lens feels
  heavy on glass): band-wide background WASHES (low-alpha tints
  behind the cells) differentiate rails while cell hues stay
  identity — one toggle apart; Paul's eye picks.
