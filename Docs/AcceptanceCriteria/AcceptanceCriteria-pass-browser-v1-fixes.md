## §2 — PAUL'S FOUR (2026-08-19)
1. **BANK-AND-FOLLOW (supersedes the banking file's pin 3)**:
   tapping OVERWRITE ROW n SWITCHES the edit target to the copy.
   Each stamp leaves a fossil; the head walks the ladder — row 1 =
   earliest, row N = the evolving edge. The lineage self-documents
   top→bottom; the strip's selected chip always answers "where am
   I." Nothing lost (the copy is identical; the trajectory
   continues). Glass confirms the feel.
2. **SUB-PASS + TRACK-FILTERED SAVES**: DRAG a region on the roll
   = the save scope (SAVE REGION, washed span); the LANE LABELS
   A–D become include-toggles (dim = excluded from the All-file +
   its stem withheld). Selection-layer only; the export machinery
   stands.
3. **PASS RANGES**: drag across pass chips = a contiguous range
   (roll washes the span; **SAVE PASSES 3–6** = one file of the
   arc). The reel is continuous; a range is a longer slice.
4. **DEEP HISTORY, two tiers**: the 32-pass ring STANDS (working
   memory, predictable). The further-back want = **THE SESSION
   TAPE**: an opt-in toggle that appends the whole session's
   emissions to a file continuously (the flight-recorder
   birthstone's simple form — nothing ever lost). Browsing deep
   history = its own later job; v1 is the file existing.

## §3 — THE CARRIAGE (Paul, 2026-08-19: next/prev instead of
## aiming — refines §2-1)
The editor's row strip gains flanking buttons: **[◀] [the 8
chips] [BANK ▶]**
- **BANK ▶** = stamp the current machine to the NEXT row (next
  empty preferred; else next) AND follow there. The ladder loop
  becomes a typewriter carriage: tweak · BANK ▶ · tweak · BANK ▶ —
  eight presses, no aiming.
- **The chips** = random access: an aimed stamp + follow (§2-1
  unchanged for the aimed case).
- **◀** = walk BACK without stamping — visit a fossil to refine
  it (edits there are live, colour-owned). **The asymmetry is
  law: forward deals, backward visits — navigation is never
  destructive.**
- Labels carry the split (BANK ▶ vs a bare ◀); the occupied/
  hollow chip states + the stamp flash apply as ruled. Glass
  tunes the next-empty-vs-next preference.

## §4 — THE TIMELINE PAIR (Paul, 2026-08-19: revert + labels —
## ideas for the Code walk-through, not build orders)
**A. REVERT TO HERE — append-only time travel.**
- Per-pass STATE SNAPSHOTS ride the ring beside the emissions
  (fullState is KB-class; 32 copies likely fine — Code verifies;
  delta-chain if heavy).
- **RESTORE (on the selected pass)** loads that snapshot as the
  live document — as ONE FORWARD EVENT: the tape keeps rolling,
  new passes append, history never rewrites. Reverting the revert
  = reverting to an earlier pass. One undo step; the reel's
  continuity unbroken ("even revert the revert" — Paul's words,
  the law).
- The payoff named: **REVERT-BY-EAR** — find the moment by
  listening to the roll, then restore. Undo counts edits; this
  browses music.
**B. PASS LABELS — the session as a changelog.**
- The undo log's acts, bucketed per pass: each chip wears a tiny
  BADGE (the surface's glyph — machine/staging/play/a processor
  icon — + a dot count for multiples); selection shows the detail
  line ("PASS 4 · +RTC · GATE 75 · BANK→3"). Focus-imagery =
  track the frontmost surface per pass (cheap).
- **Unbadged passes = pure playing** — performance and editing
  self-distinguish at a glance (emergent, free, lovely).
- Chrome-quiet governs the badges (one glyph, tiny; detail on
  selection only).
The trio, named for the record: **the TAPE (sound) · the
SNAPSHOTS (state) · the LOG (changes)** — the reel as the
session's whole memory.
