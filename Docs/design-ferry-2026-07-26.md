## 5. CAPTURE RETENTION — design guidance for the flight-recorder build
Sizing at 120bpm (for the record): events ≈24B fixed records → ~1.7MB/hr
busy playing; naive per-pass checkpoints (~8KB × ~900/hr) ≈ 7MB/hr; naive
total 10–15MB/hr vs a prudent 50–100MB extension budget = hours of
headroom even unbounded. THE DESIGN (bounded by construction):
① **checkpoint DEDUPE** — unchanged documents reference the prior
checkpoint (hash-compare; value-type sharing) → capture falls to
~1–2MB/hr; ② **the RING** — RAM holds only the replay-buffer tail
(measured in passes, as specced); ③ **DISK DRAIN** — Time-Machine
horizons drain to the App Group container (an hour ≈ one photo).
RAM never exceeds the ring; nothing unbounded exists; tempo only scales
checkpoint rate linearly. Memory is a non-problem BY DESIGN, not by luck.
