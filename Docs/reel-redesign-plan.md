# Reel redesign plan (2026-10-24)

Browsable twin (what to hand to a person; has the interactive mockup): https://claude.ai/code/artifact/7753f131-cf41-4cae-a79b-f88b8bcfe702 — and the same page, self-contained, in `Docs/reel-redesign-mockup-2026-10-24.html` (open it in a browser). This file is the copy Claude reads. Findings behind it: `Docs/pending-tasks.md`, "REEL USABILITY REVIEW" (REEL-1 … REEL-12). **Status: phase 0 DONE and landed (2026-10-25); phase 1 IN PROGRESS — 1a (tape store) + 1b (records beside the old reel, verified against it) done; 1c (replay keeps recording), 1d (saved to disk) to do; phases 2-4 not started.**

## The brief (Paul, 2026-10-24)
Replay any MIDI **from the start of the session onwards**; export **several** bits they like (not one range); the screen should feel designed, not written — **more visual, less text**; **no "rotate to landscape"**; keep the **whole session** if possible.

## Root cause
The reel is built around "passes" (a 64-slot ring of 16-beat loops, `ReelDeck`), not around time. Measured: 64 × 8,192 × 16 B = 8 MiB fixed; 8½ min at 120 BPM, 3½ at 299; recording freezes while browsing/replaying because `Kernel` SKIPS `router.process` during replay (`if reel.state == .replaying … else { router.process … }`); replay loops one pass phase-locked to the global 16-beat cycle (seen 70% in, 3 s after a tap); every export is named `Fourfold-All.mid` / `Fourfold-A.mid` (the second overwrites the first); SAVE does nothing silently with no selection or an empty output; no accessibility labels; the rotate prompt is a dead end in a plug-in window.

## The new screen (see the mockup)
Three views of one tape: **overview** (whole session, stacked by lane, now = right edge, stars for keeps) → **tape** (window ≈ 48 bars: bar numbers, clock time, ×n repeat brackets replacing REMOVE DUPLICATES, selection with snapping handles, keeps flagged) → **close-up** (selection as a piano roll, notes in LANE colours). Controls: back to start · play from here onward then back to live · loop selection · **Keep N bars** · Export (n). Keeps are chips with a tiny drawn picture; tick several to export. A LIVE/TAPE pill says what you hear (press TAPE to return to live). Layout is one pure function of window size with three shapes: **wide**, **tall**, **small** (AUM plug-in window: no tape strip; the overview selects directly; keeps collapse to one button). The empty state is drawn ("Play to start the tape."). Vocabulary left: Reel, Live, Tape, Keep, Export, bars, time. Palette = the app's own tokens (`Docs/fourstep-design-tokens.md`): ground #15161A, panel #2A2D34, selection #DFE3EA, lane colours #F25959 #59BFF2 #F2BF40 #8CD973 for content; the reel's old cyan goes. iOS 15 floor: Canvas painters only, no iOS 16 SwiftUI.

## Whole session: the numbers
Measured from the 26 allocation-audit scenarios (events counted at the harness, both cables): mean 4,766 / max 16,416 events per 128 beats. One 8-byte record per event per OUTPUT (the "All" copy is rebuilt on export): **149 B/beat mean, 513 B/beat densest**. Per hour at 120 BPM: 1.0 MiB mean / 3.5 MiB densest; 8 h: 8.2 / 28.2 MiB; at 299 BPM 8 h: 20.4 / 70.2 MiB. Per-bar summary (4 lanes × 4 B): 225 KiB for 8 h. Keep resident tape ≤ 8 MiB (today's budget); spill older chunks to a file; the session survives relaunch.

## Phases (each shippable; S = hours, M = days, L = a week+)
**0 · Stop the damage (S, low risk) — DONE 2026-10-25** (named by PASSES for now: `Fourfold 2026-10-25 14-52-07 passes 8-9 A.mid`, bars after phase 1). Unique, descriptive export names (`Fourfold · bars 97–104 · A · 14-52-07.mid`, a pure tested function reused later); SAVE disabled with a one-line reason (nothing selected / output empty, per-output note counts); one-line notice when older passes dropped. Closes REEL-5, REEL-6, softens REEL-1. Proof: naming unit tests; tap test saving twice → two files; tap tests for both disabled states.
**1 · The session tape (L, medium).** New `SessionTape` in `Fourfold/Engine`: append-only ~64 KiB chunks from a pool the main thread tops up (lock-free; pool dry ⇒ count + drop, never allocate), 8-byte events tagged output + lane, session clock 1/960 beat from first play, tempo map, per-bar summaries (density per lane, pitch range, fingerprint). Replay stops skipping the engine: it keeps running into a silent recording tap. 8 MiB resident, spill to a file, survives relaunch. Old browser reads it through an adapter (16-beat slices) so the app ships in between. Closes REEL-1, REEL-2, REEL-12 (tempo, persistence), lane tag for REEL-8. Proof: golden identical; `run.sh --alloc` zero incl. a new record-while-replaying scenario; differential test (same pass through old deck vs new tape → identical export bytes); 4 simulated hours in a unit test with a memory ceiling; soak with random replay start/stop; relaunch test.
**2 · Replay from anywhere, onward (M, medium).** Position = host beat − anchor (derived, nothing accumulated); modes: from here → live, loop selection, live now; hand-back flushes tape notes and unmutes the already-running engine; transport stop returns to live; UI told LIVE/TAPE. Closes REEL-3. Proof: sample-accuracy test (replayed offsets == recorded, buffers 64–4096, stop/start, tempo change); extended soak; hand-back edge tests (no orphan offs / stuck notes).
**3 · The new screen (L, medium).** Rewrite `FourfoldReel.swift`; pure `reelLayout(size:)` (3 shapes + floors) and pure selection/zoom/snap maths; lane colours; ×n brackets from bar fingerprints; drawn empty state; delete the rotate prompt; VoiceOver (selection start/length adjustable, play/keep/export as actions, keeps as a list, spoken summary of the close-up). Closes REEL-7, 9 (part), 10, 11, the visual brief. Proof: layout fuzz 480×320 → 13" × 4 orientations; screenshots on all six iPad simulators looked at; reel added to the accessibility audit + tap tests; frame rate with an 8-hour tape owed on a device.
**4 · Keep and export (M, low–medium).** A keep = a range on the tape + auto name, stored with the session. Triggers: ★ in the reel, ★ in the standalone transport bar, long-press the header reel icon (no spare header width), and an AU parameter (NEW stable address — never renumber) so AUM / a foot switch can trigger it. Grab length 2/4/8/16/32 bars (default 8). Export: one file per keep or joined; mix / per output / per lane; real tempo track; new name every time; confirmation with Share + Show in Files; drag a chip out as a .mid is a stretch. Closes REEL-4, 5 (final), 9, 12 (export tempo). Proof: recorded fixture exported, parsed back and compared note for note; collision tests; tap tests; an AUM device check. **Privacy manifest:** reading file dates or free disk space needs a required-reason category in BOTH manifests (CLAUDE.md rule).

## Decisions still Paul's (recommendation first)
1. **What is "the session"?** From first play after launch, kept on disk, survives relaunch, ends on a confirmed "New session"; cap 24 h with a warning at 80%.
2. **Replay replaces live or layers on top?** Replace (today's behaviour; no doubled notes); layering is a cheap later switch.
3. **How to keep?** ★ in reel + app transport bar + long-press header icon + AU parameter; default 8 bars. Does a hands-free trigger matter?
4. **Bars or passes?** Bars (host time signature); passes leave the screen.
5. **Files out of AUM via the share sheet only?** Yes for now (the plug-in's folder is hidden; an App Group is the alternative).

## Risks / not verified
Audio-thread hand-off (alloc audit + soak are the gates); render-order change in `Kernel` (golden + replay scenarios); AUv3 extension memory ceiling is undocumented (hence 8 MiB); lands in `Fourfold/Engine` only — the frozen 8x8 reel keeps its behaviour; **another instance is working on the page's small-window fallback — share its minimum size**; iOS 15 floor (nothing has run on iOS 15). Not verified: nothing is built, mockup notes are generated (default document's rhythms + two lanes), storage numbers are from audit note counts not a real long session, nothing was heard, no real-iPad hit-size or zoom judgement, and 8 bars / a foot switch are guesses.
