## THE SIX RULES (the hierarchy law)
1. **THE HERO LAW.** Every card opens with its ★★★ hero — first
   under the divider, full-width, extra vertical padding, and a
   **2pt accent bar on its left edge** (the only control that
   wears one). Matrices/lanes are already visually heroic; this
   rule mostly = ORDER + the bar + breathing room. A hero never
   shares a row.
2. **THREE BANDS.** PRIMARY = the hero(s). SECONDARY (★★) =
   compact fields, pairable two-per-row in Pass 2. TERTIARY (★)
   = **THE OPTIONS CLUSTER**: all minor toggles gathered into ONE
   compact row at the card's foot — small inline chips under a
   single "OPTIONS" field label (FIT 1 BEAT · INVERT · RAKE ·
   DRY NOTE · SPILL…). No ★ toggle ever eats a full row again.
3. **ONE SPECIES RETIRES ALL THREE LEGACIES — the NUDGE PAIR
   generalises.** ◀ value ▶ with tap = ±1, hold = repeat, **drag
   the value = scrub**. This one widget replaces:
   - `grid16` everywhere (ECHO REPEATS ◀4▶ · DELAY ◀3/16▶ ·
     EUCLID HITS/STEPS),
   - numeric-as-radio (OCTAVES ◀2▶ · SIZE MIN/MAX · HITS ·
     REPEATS),
   - **CHANNEL's 17-chip wall → ◀ WIRE ▶** (cycles WIRE·1–16),
   - and it IS the ratified ROTATE control (one grammar for
     every number in the app).
   `seg` remains ONLY for true enums (words, not numbers).
4. **SECTION THE LONG CARDS.** Quiet section labels (field-label
   style + a hairline): **ECHO → TIMING (repeats·sync·delay·
   nudge) · TONE (1st·fade·pitch) · TAIL (dry·spill·route)**;
   MOD groups per-source; WEAVE per-mode. Below-the-fold stops
   being a mystery.
5. **THE FIXED ORDER GRAMMAR** (pattern cards read identically):
   HERO → core params → phase (NEW CHORD) → pattern chrome in
   the fixed order **GRID · ROTATE(◀n▶) · SPAN** → the OPTIONS
   cluster. Inconsistent ordering ends.
6. **PASS 2 (two columns, on Paul's device eye):** heroes span
   both columns; ★★ fields pair up; the options cluster = one
   row. The nudge-pair conversions make most ★★ rows half-width
   naturally — Pass 2 gets cheap.
